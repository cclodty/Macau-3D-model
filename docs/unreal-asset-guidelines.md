# Unreal Nanite、LOD 與碰撞製作規範

本文件用於統一澳門場景資產的 Nanite 選擇、傳統簡化版本及碰撞製作方式。資產匯入目標 Unreal 版本前，應依照以下規則評估並記錄結果。

## Nanite 候選分類

下列資產預設列為 **Nanite 候選**：

- 建築主體。
- 高密度雕刻構件。
- 不透明的大型靜態物件。

「候選」不代表可直接啟用。製作者仍須在目標 Unreal 版本、目標平台及實際材質設定下確認顯示、效能與功能符合需求。

## 必須先實測的資產

以下資產不可只依面數或外觀決定是否使用 Nanite，必須先在目標 Unreal 版本實測，再選擇 Nanite 或傳統 LOD：

| 資產類型 | 實測重點 |
| --- | --- |
| 欄杆 | 細小輪廓、遠距顯示及碰撞需求 |
| 植物 | 葉片材質、風動或其他變形，以及遠距顯示 |
| 透明玻璃 | 透明材質在目標版本所採用的渲染路徑 |
| 使用 opacity mask 的細小物件 | 遮罩邊緣、遠距穩定性及效能 |
| 特殊變形或互動資產 | 動畫、材質變形、狀態切換及互動功能 |

測試後應在資產紀錄中註明目標 Unreal 版本、目標平台、測試場景、最終方案及選擇原因，避免升級引擎後沿用未驗證的結論。

## 傳統簡化版本

即使資產計劃使用 Nanite，下列用途仍須準備傳統簡化版本：

- 遠景 skyline。
- 大量重複的小型街道設施。
- 低階硬件或非 Nanite fallback。
- 需要簡單碰撞或導航計算的物件。

簡化版本應保留影響輪廓、遮擋及玩法的主要形狀，移除遠距不可辨識的雕刻、內部面及微小構件。大量重複物件須以代表性密度在場景中驗證，而非只測試單一實例。

## 碰撞製作

### 簡單道具

簡單道具使用 Unreal 自動產生的簡單碰撞。匯入後須檢查碰撞是否包覆主要體積，且不會明顯阻擋預期的角色通行空間。

### 自訂凸形碰撞

下列資產須製作以 `UCX_` 命名的凸形碰撞：

- 建築入口。
- 樓梯。
- 欄杆。
- 具有特殊通行形狀的物件。

每個 `UCX_` mesh 必須維持凸形；凹形通行區域應拆成數個簡潔的凸形組件。命名須對應視覺 mesh，例如：

```text
BuildingEntrance_01
UCX_BuildingEntrance_01_00
UCX_BuildingEntrance_01_01
```

### 禁止事項

- 不可將高精度視覺 mesh 預設用作 complex collision。
- 不可以 Nanite 視覺細節取代玩法碰撞的規劃。
- 不可讓裝飾細節、微小凹槽或不可到達的內部結構增加碰撞複雜度。

只有經過個別評估、確實需要逐多邊形查詢且已驗證效能的例外資產，才可採用 complex collision；例外必須記錄用途及測試結果。

## 道路、步道與導航

道路、行人路及其他可步行區域必須建立獨立、簡潔且連續的碰撞表面，確保：

- 角色移動時不會被視覺 mesh 的接縫、坑洞或微小高差卡住。
- 樓梯、路緣及斜坡的碰撞符合預期通行方式。
- NavMesh 可形成連續、穩定的可導航區域。
- 不可通行邊界與場景中的實際阻擋一致。

碰撞表面不必複製鋪面紋理、排水溝或其他純視覺細節；應只保留會影響移動與導航的形狀。
